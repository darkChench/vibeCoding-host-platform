## 2. 一句话定义

面向 Modbus RTU 嵌入式设备的 Windows 上位机，支持串口连接、实时数据采集、参数物模型配置、控制下发、报警监控、历史查询，并集成 AI 助手用自然语言操作设备。

## 3. 背景与目标

### 3.1 背景

- 不同型号设备的 Modbus 寄存器读写地址不同，现有上位机不满足按设备型号定义不同物模型展示及参数读写。
- 现场缺乏好用的、可扩展的、能直观调试报文的上位机。

### 3.2 目标（原型已实现对应功能）

- **目标 1**：串口连接与调试——参数配置（波特率/数据位/校验位）、HEX/ASCII 双编码收发、自动发送、行结束符、发送历史（最近 20 条）、原始报文日志。✅ 原型已实现
- **目标 2**：参数物模型定义——按设备定义采样参数（地址/类型/权限/单位/范围），支持增删改查与校验。✅ 原型已实现
- **目标 3**：实时监控与趋势——按采样参数动态展示实时值与趋势曲线，支持曲线显隐筛选。✅ 原型已实现
- **目标 4**：Modbus 协议层——参数表自动翻译为真实 Modbus RTU 报文（含 CRC16），模拟设备回包，报文自动注入串口日志。✅ 原型已实现
- **目标 5**：AI 助手——自然语言操作设备（查采样/报警/趋势/设备状态），LLM 通过 function calling 调用工具函数。✅ 原型已实现（模拟响应）

### 3.3 不做什么（当前版本）

- 不实现 TCP 通信（仅 RS485 串口）
- 不做多设备型号区分（当前单一设备型号）
- 不做用户权限系统（PRD §10 暂不实现）
- 不做云端数据同步（纯本地）

## 6. 设备与通信

### 6.1 设备

单一设备型号（如 RDM 传感器），通过 RS485 总线连接。从站地址可在参数页配置（1-247）。

### 6.2 通信协议

| 协议 | 用途 | 关键参数 |
| :--- | :--- | :--- |
| Modbus RTU | 设备数据读写 | 从站地址、波特率、功能码 03/06 |

### 6.3 通信策略

- 采集周期：1s（监控页实时刷新）
- 协议层自动组帧（用户不碰报文格式）
- 串口页保留手动 HEX 收发（调试用，独立于协议层）

## 8. 技术约束（硬约束）

- **UI 层禁止直接访问串口**（分层）
- **协议层是内部逻辑**，报文格式不让用户碰
- **参数表是页面可配**，协议层据此组帧
- 所有控制命令必须有确认和失败处理
- API Key 等敏感信息本地存储，不提交 Git
- 打包发布前必须通过质量门禁（见 `docs/references/quality-gates-and-pitfalls-hmi.md`）

## 9. 验收标准（关键项）

| A-006 | AI 助手 | 自然语言查询走工具→协议层 |
