## 3. 背景与目标

### 3.1 背景

- 当前现场或业务遇到的问题：没有好用的上位机页面
- 现有方案的不足：不同型号设备modbus寄存器读写地址不同，目前不满足根据不同型号设备定义不同物模型展示及参数读写
- 为什么需要开发新的上位机：现有上位机都不满足业务要求

### 3.2 目标

- 目标 1：实现串口连接与断开（波特率、数据位、校验位选择、日志接收、与日志发送，支持ASCII和HEX双编码收发切换、支持根据输入的ms时间勾选自动发送功能、支持最近20条发送命令的保存和查看，支持结尾是否带\r\n的选择）
- 目标 2：实现针对不同设备的参数物模型定义
- 目标 3：实现对采样参数的曲线趋势查看与分析

## 8. 功能需求

### 8.1 设备连接

- 用户可以配置设备连接参数。
- 用户可以手动连接、断开和重新连接设备。
- 系统必须显示设备在线、离线、通信异常等状态。

### 8.2 实时监控

- 显示设备物模型（采样类型）的实时值、单位、状态和更新时间。
- 支持异常值、超限值和通信失败状态的可视化提示。

### 8.3 参数配置

- 支持读取设备当前参数。
- 支持修改允许写入的参数。
- 写入前必须进行范围校验和二次确认。
- 写入失败必须显示明确错误原因。

### 8.4 控制下发

- 控制命令必须区分普通操作和高风险操作。
- 高风险操作必须有二次确认、权限校验和执行结果反馈。
- 控制失败不得被静默忽略。

### 8.5 报警管理

- 支持报警触发、恢复、确认和历史查询。
- 报警规则必须可追溯到点位、阈值和触发条件。

### 8.6 历史数据与报表

- 支持按时间范围查询历史数据。
- 支持导出 CSV 或 Excel。
- 支持关键指标趋势查看。

### 8.7 日志与诊断

- 记录用户操作日志。
- 记录通信日志和异常日志。
- 支持导出诊断包，便于现场排查。

## 12. 质量门禁

开发完成前必须通过以下检查：

- 协议解析有测试用例。
- 设备模拟器能跑通核心流程。
- 断线、超时、重连、错误帧有测试或手工验证记录。
- 控制命令有权限、确认、失败反馈和日志。
- 配置文件错误时能给出明确错误信息。
- 打包后的程序能在目标机器运行。

推荐命令：

```bash
make lint
make test
make test-protocol
make run-simulator
make package
```
